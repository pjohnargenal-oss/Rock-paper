DORMITORY PROJECT - UI / LOGIN SECURITY UPDATE

Included in this package:
- Refreshed shared UI styling for sidebar, buttons, forms, tables, badges and mobile layout.
- SweetAlert2 remains loaded by the shared header (existing integration retained).
- Public self-registration is disabled; accounts must be provisioned by an administrator.
- Login no longer accepts plain-text passwords. Existing accounts must have password_hash values generated by PHP password_hash().
- Existing Admin / Manager / Tenant role model is supported by database/upgrade_v2.sql.

IMPORTANT SETUP:
1. Back up your current dormitory_db before running any SQL.
2. If not already applied, run database/upgrade_v2.sql in MySQL Workbench. It is additive but check your current schema first; do not rerun if you already applied it unless you have reviewed the ALTER statements.
3. Create an administrator using create_admin.php only if an Admin account does not already exist. The current setup script creates username `admin` with a temporary password shown in that script. Sign in and change it immediately.
4. DELETE create_admin.php from the web folder immediately after successful admin creation.
5. Existing plain-text passwords will no longer work. Reset them to password_hash values through the admin account workflow or a secure one-time reset procedure.

LIMITATIONS / NOT YET IMPLEMENTED:
- This delivery does not yet implement a complete Archive/Restore workflow across every module. Do not treat the existing Delete actions as archival until that feature is completed.
- Some modules in the supplied source ZIP have incomplete CRUD coverage. This package does not claim that every module has full create/list/edit/archive functionality.
- No database records were intentionally deleted or migrated by this package.
